VERDICT
Functional tests below passed. The pre-split deep copy is a significant
performance problem in the current implementation. It is paid on EVERY H2
callback before the first changed/held output, not just on the first rewrite.
FlowCtx currently starts this path for recognized H2 even without an enabled
content webhook. The two-parser path after splitting is substantially cheaper
than repeatedly preparing and discarding the deep copy.
No runtime optimization was made during this measurement task.

MEASUREMENT METHOD
AMD Ryzen 7 3700X; GCC Release -O3, -DNDEBUG, LTO, BUILD_RELEASE.
Single process pinned to logical CPU 14, after our builds/tests had finished.
Normal host activity was not disabled; these are microbenchmarks, not network
latency/throughput results. Seven warmed batches with rotated path order.
Numbers below are median microseconds per callback/operation; min/max and
sample counts are in benchmark-final.log. They are NOT request percentiles.
Payload means H2 DATA body bytes (wire size also includes the 9-byte header).
Windows were explicitly increased so the workload stays on the valid parser
path, and each timed sample checks resulting body counters and validity.
Initialization and payload allocation are outside timed intervals.
The one-parser baseline uses seed(), the same parser + annotation code without
forking or a webhook; it is NOT a separately built old proxy binary.

CODE-LEVEL FINDINGS (not a sampled allocation profile)
1. ProtocolViews::begin forks before observing every input until split.
2. protocol_fork first copies EngineCtx (including std::any protocol state),
   then replaces that state with clone_protocol: stream containers are copied
   once by the EngineCtx copy and again by clone_protocol.
3. Copying each HPACK decoder rebuilds its immutable canonical Huffman tree.
4. app_HttpRequest copy includes up to 10,000 historical HTTP request records.
These are independent optimization candidates. Sharing immutable structures
does not justify sharing mutable HPACK tables or endpoint protocol state.
