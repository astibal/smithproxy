# Bug audit

This file records product and regression-harness defects found while expanding
test coverage. Each entry names the failure mode, impact, correction and
regression evidence so a coverage increase remains reviewable as more than a
percentage change.

| ID | Area | Finding and impact | Correction | Regression evidence |
| --- | --- | --- | --- | --- |
| PXM-001 | Proxy connect | A failed upstream `connect()` returned an invalid descriptor, but the proxy registered it with the event loop and reported success. A numeric sign check alone is not sufficient because UDP and multiplexed transports intentionally use negative virtual descriptors. | Ask the endpoint transport to validate the returned descriptor before monitor/handler registration and ownership transfer; real transports reject syscall errors while virtual transports recognize only their live tokens. | `ProxyMakerUtils.RejectsFailedUpstreamBeforeRegisteringHandlers`, `AcceptsTransportValidatedVirtualDescriptor`, and `MFFlowCom.KeepsStreamIoButReportsUdpToPolicy`. |
| PXM-002 | Proxy ownership | `route_existing()` temporarily adopted a caller-owned raw pointer in a `unique_ptr`. An exception while routing could delete an object still owned by the caller. | Route through a non-owning overload; the owning overload delegates with `get()`. | Production build plus the focused ProxyMaker ownership tests exercise the shared route/connect helper boundary. |
| PXM-003 | Policy routing | Failure to select or apply a configured routing target was logged but policy processing continued toward the original destination. That made a routing failure fail open. | Propagate routing failure from `policy()` and abort proxy creation. | Full native suite; routing errors now have an explicit false return path. |
| PXM-004 | UDP accept | The accepted UDP context was transferred into a child proxy before source-address resolution. On resolution failure the context was manually deleted, then deleted again when the child proxy unwound. | Resolve the source before transferring ownership to the child proxy. | ASan build and native/dataplane lifecycle runs; ownership is transferred only after the failing operation. |
| PXM-005 | Transparent source | `std::stoi` accepted trailing bytes and negative values, which could wrap into an `unsigned short` source port. | Parse the complete decimal field with `from_chars` and accept only `1..65535`. | `ProxyMakerUtils.ParsesOnlyCompleteValidSourcePorts` |
| PXM-006 | Proxy setup | Proxy creation, policy, routing and SNAT paths dereferenced missing contexts or transports on partially constructed flows. | Share one validated endpoint precondition across make/policy/route/SNAT before accessing either communication object. | `ProxyMakerUtils.RejectsMissingEndpointTransportsBeforeProxySetup`, `RejectsFailedUpstreamBeforeRegisteringHandlers`, and the full native suite. |
| PXM-007 | Stream half-close | The drain grace period treated an allocated peer object as a live writable peer. During tightly timed bidirectional shutdown it could retain a session and re-arm a descriptor that the transport had already invalidated. | Hold a half-closed session only while the peer has pending output and its descriptor is valid according to that peer's transport; this preserves negative virtual UDP/MultiFlow descriptors. | `MitmProxyLifecycle.HalfCloseRequiresPendingDataOnLivePeer` and `HalfCloseAcceptsTransportValidatedVirtualPeer`. |
| PXM-008 | Accepted-context ownership | Transparent TCP/UDP, SOCKS, HTTP CONNECT and multiplexed-flow handoff passed newly allocated contexts and child proxies as unrelated raw pointers. Invalid setup returned without an owner, while an exception between acceptor release and child registration could leak the context and its descriptor; transparent callers also dereferenced a null proxy result. | Make the generic accept callbacks consume `unique_ptr<baseHostCX>`, retain child proxies in `unique_ptr`s, release each endpoint only after the child registers it, remove the raw `MasterProxy::add_proxy` ownership API, and reject failed child construction before logging/policy work. | `ProxyLifecycle.ExceptionDuringAcceptedContextHandoffClosesExactlyOnce`, production build, and privileged TCP/UDP/SOCKS/CONNECT/MultiFlow lifecycle suites. |
| PXM-009 | Stream half-close timer | The five-second drain deadline was initially evaluated only when another socket error called `on_half_close()` again. Moving it to the periodic timer was still insufficient: an idle event loop slept for ten seconds, the tick comparison excluded the exact boundary, and a dead child was moved to a traffic-reaped deferred-destruction queue without first closing its transports. A client could receive its delayed response but time out forever waiting for final EOF. | Cap idle poll sleep to the timer's one-second resolution, trigger at the exact boundary, tolerate a backward wall-clock adjustment, evaluate the active half-close deadline without further descriptor events, remove a child that expires during the same master tick, and shut down/unregister its transports immediately while retaining deferred object destruction for callback safety. | `MitmProxyLifecycle.HalfCloseGraceExpiresWithoutAnotherSocketError`, transfer lifecycle suite, and privileged delayed-response-after-`SHUT_WR` E2E. |
| PXM-010 | Multi-peer transfer | Once a destination crossed the fast-copy threshold, `to_write(buffer&)` moved the source buffer into the first peer. In a one-to-many proxy the remaining active or delayed peers then observed an empty source and silently missed the payload. | Preserve the source while dispatching to all but the final destination, then allow the final destination to use the existing zero-copy swap. Ordinary one-to-one traffic keeps the same hot path. | `TransferLifecycle.FanoutPreservesSourceUntilFinalFastlaneDestination`, bounded-drain transfer matrix and privileged smoke. |
| PXM-011 | Full-duplex backpressure | Pausing reads on one side replaced that descriptor's complete epoll interest mask. If the same connection already had output queued in the independent direction, its `EPOLLOUT` interest was removed and the transfer could wait for an unrelated event or the next poll timeout. Restoring reads likewise forced a read-only mask. | Derive the side-wide monitor mask per connection: pause only reads while retaining write interest for an opening connection, non-empty output queue or protocol-level write transition, and retain that interest when reads resume. Listening sockets are kept read-only so their persistent `opening` flag cannot create a writable-event spin. | `ProxyLifecycle.ReadBackpressurePreservesPendingFullDuplexWrite`, `ReadBackpressureDoesNotAddWriteInterestToListener`, complete transfer testbed and privileged bounded-drain transfer matrix. |
| PXM-012 | TLS backpressure rescan | When a peer output queue crossed `host_write_full`, `baseHostCX::read()` used the read-only rescan path. That path temporarily removed the descriptor and restored only `EPOLLIN`, losing an independent TLS `WANT_WRITE` transition when no application bytes were queued. Progress could then wait for an unrelated event. | Let transports report protocol-level write-event demand and select the `EPOLLIN|EPOLLOUT` rescan path for queued output, an opening connection or TLS `WANT_WRITE`; ordinary read-only rescans remain unchanged. | `TransferLifecycle.ReadRescanPreservesProtocolWriteEvent`, complete transfer testbed and privileged bounded-drain transfer matrix. |
| PXM-013 | TCP read half-close | A zero-length stream read was classified as a fatal connection error and immediately called `shutdown(SHUT_RDWR)`. A client that sent a complete request, closed only its write half and continued reading could therefore lose a delayed server response. EOF following useful bytes in the same drain batch had the same effect; after a delayed response drained, its write-only monitor could also remain permanently writable and spin. | Track read EOF independently from fatal transport errors, stop only read monitoring, retain protocol/queued write readiness for delayed output, remove it after the queue drains, and keep the peer direction alive for the bounded half-close grace period. This deliberately does not synthesize an upstream FIN; protocols whose origin requires EOF framing need a larger directional-FIN state machine. | `TransferLifecycle.PreservesReadProgressWhenPeerThenCloses`, `ProxyLifecycle.ReadEofKeepsWriteHalfAvailableForDelayedResponse`, complete transfer testbed and transparent HTTP E2E with a delayed response after client `SHUT_WR`. |
| PXM-014 | Stream event classification | The epoll adapter merged clean `EPOLLHUP` with `EPOLLERR`; the poll loop then unconditionally marked the owning proxy dead. It also did not subscribe to `EPOLLRDHUP`, so a directional peer close depended on incidental read readiness and could be mistaken for a fatal full close. | Subscribe read-monitored descriptors to `EPOLLRDHUP`, keep peer-shutdown events separate from socket errors, and route HUP/RDHUP through the normal read path so final bytes are drained before EOF is recorded. Only `EPOLLERR` remains unconditionally fatal. | `EpollLifecycle.PeerHalfCloseIsReadableButNotSocketError`, transfer lifecycle suite and privileged delayed-half-close E2E. |
| PXM-015 | Permanent stream reconnect | A reconnected `baseHostCX` retained the previous stream's read-EOF flag, so the new connection could remain permanently unreadable. Each reconnect also overwrote the one descriptor deferred for destruction, leaking the prior retired descriptor. | Retire the previously shut-down descriptor before opening its replacement and reset directional EOF state for the new stream. | `TransferLifecycle.ReconnectResetsReadEofAndClosesRetiredDescriptor`. |
| PXM-016 | Permanent connect failure | A failed left/right permanent connection abandoned its newly allocated context and transport. The same error path formatted the integer result as `%s`, which could dereference it as a pointer while logging the failure. | Keep the candidate context in a `unique_ptr` until a successful connection transfers ownership, and use the correct integer log format on both sides. | `ProxyLifecycle.FailedPermanentConnectReleasesBothSideContexts`. |
| TST-001 | QUIC soak | The origin counted a completed short-lived certificate-probe handshake on a later polling tick. A peer close between accept and that tick made a valid handshake disappear from the counter. | Record the handshake immediately when OpenSSL publishes the accepted connection, retaining the later check only as a fallback. | Repeated `QuicTestbed.RepeatedVerifiedReconnectsReleaseEveryIdleSession` soak. |
| TST-002 | QUIC interop | The OpenSSL client closed at stdin EOF immediately after a verified QUIC handshake, racing delivery of its first application-stream payload and making the external interop test deterministically fail. | Keep `s_client` alive until the origin confirms the echo, with a bounded poll and cleanup. | `external.quic_interop` with the system OpenSSL QUIC client. |
| TST-003 | Privileged PCAP tests | Legacy PCAP unit tests reused fixed files in `/tmp` and passed their unchecked `fopen()` result to `fileno()`. Under root, Linux sticky-directory protection rejected truncating a user-owned prior artifact and the coverage suite segfaulted; concurrent runs could also overwrite each other. | Generate every throwaway PCAP/PCAPNG through an anonymous `tmpfile()` and assert successful creation before using its descriptor. | Root `PcapTest.*` and `NgTest.*` runs plus the privileged coverage profile. |
| TST-004 | Privileged Wireshark tests | `tshark` intentionally disables user Lua dissectors under EUID 0, so a root coverage run rejected the otherwise valid `sphttp3` display filter and reported two false integration failures. | Explicitly skip Lua-dissector assertions under root with the security limitation in the reason; retain their mandatory execution in the ordinary unprivileged native layer. | `tools/wireshark/test_spquic.py` passes 2/2 unprivileged and reports two explicit skips under root. |
| TST-005 | Dataplane cleanup | Cleanup compared complete host link and route snapshots. An unrelated VM attaching to an existing bridge during the seven-minute coverage dataplane run changed carrier state and the derived `linkdown` route flag, falsely failing an otherwise clean lab. | Check the lab's exact veths, namespaces and listeners explicitly; compare persistent host addressing/routes while excluding unrelated interface churn and carrier-derived flags. | Privileged coverage dataplane cleanup with an independently active VM interface. |
| TST-006 | Diagnostic trace configuration | `TLS_EVASION_TRACE=1` replaced only a semicolon-terminated global log-level assignment, while the current base configuration omits that semicolon. Per-component proxy/epoll levels also remained lower, and the runner always selected a release-like build which compiles detailed traces out. Diagnostic reruns therefore silently discarded the event trace needed to analyze timing failures. | Match the global assignment independently of optional syntax, raise the proxy and epoll component levels, fail preparation explicitly if any setting cannot be found, and allow a validated `PATCH_TEST_BUILD_TYPE=Debug` trace build. | Generated trace configuration plus patch-runner argument/self-tests; the cheatsheet records the reproducible Debug trace invocation. |
| TST-007 | Incremental coverage after source removal | GCC notes for deleted or renamed source files can remain in an incremental build tree. The report accepted their old source paths into its inventory and then crashed while rendering the now-missing file, making coverage unusable after ordinary cleanup/refactoring. | Admit only current regular product-source files; stale `.gcno`/`.gcda` entries are ignored rather than counted or rendered. | `unit.patch_runner_coverage_report` exercises present, deleted and recreated source states; regenerating coverage from the existing async-OCSP build tree succeeds. |
| TST-012 | Base TLS trust probe accidentally required public revocation evidence | The synthetic smoke origin intentionally uses a private CA so the client/proxy trust split is tested in isolation, but it inherited strict Certificate Transparency and OCSP controls. Its SCT/OCSP-free certificate therefore produced a replacement 403 rather than testing the intended trust path, and `curl -f` discarded the diagnostic body. | Disable CT and OCSP only in the generated lab's base TLS profile, leaving chain and hostname validation enabled and dedicated TLS tests responsible for revocation evidence. Preserve non-2xx response bodies with `--fail-with-body`. | Privileged `sanity --suite smoke` requires both IPv4 and IPv6 PASS TLS responses from the private-CA origin and a clean lab teardown. |
| OCS-001 | Experimental async OCSP | The never-deployed deferred OCSP path had an independent nonblocking state machine, descriptor ownership and timeout semantics, multiplying revocation failure modes without a production caller. | Remove the complete experiment: `OcspQuery`, `AsyncOCSP`, `AsyncOcspInvoker`, proxy fields, build entries and dedicated tests. Keep the deployed synchronous and stapled OCSP paths. | Production build and the synchronous OCSP/CRL integration and sanitizer matrices. |
| OCS-002 | OCSP parsing | Public request/check helpers and signed-response CertID parsing trusted null or incomplete OpenSSL objects. Malformed inputs could be dereferenced instead of producing an unknown/fail-closed result. | Validate request components, response singles, CertID fields and digest lookup before use. | `TLSIntegration.OCSPRequestPreparationRejectsIncompleteInputs`, signed-response matrix and revocation fuzzer. |
| OCS-003 | OCSP responders | The synchronous responder loop tested a stale local variable, so it continued after a definitive GOOD/REVOKED result and allowed a later responder to replace it. | Stop at the first current, signed, matching definitive response. | Existing multi-entry signed-response tests plus full TLS integration suite. |
| ASY-001 | Async socket lifecycle | Completion unregistered an async task by resetting its terminal state to `INIT`. Non-owning registrations also retained a borrowed descriptor number, so a later destructor could unregister an unrelated socket after fd reuse. | Preserve terminal state while detaching after completion, and always clear the registration's descriptor and communication pointers after unregistration without closing borrowed fds. | `TLSIntegration.AsyncSocketCompletionKeepsTerminalStateAndForgetsBorrowedFd`. |
| ASY-002 | Async timeout result | The common timeout path invoked a task callback without letting the derived protocol publish a timeout result. | Add a protocol timeout hook before detaching so derived tasks can publish their terminal result. | `TLSIntegration.AsyncSocketTimeoutPublishesDerivedFailureBeforeCallback`. |
| ASY-003 | Async polling state | `IAsyncTask::finished()` returned the state produced by `update()` but never stored it. Callers polling through this public API could observe completion while the task itself continued to report `INIT` or `RUNNING`. | Store every state transition returned by `update()` before reporting whether it is terminal; reject invalid registration descriptors/owners without changing state. | `TLSIntegration.AsyncSocketRejectsInvalidRegistrationAndPollingStoresState`. |
| DNS-001 | Asynchronous SOCKS DNS | DNS request setup returns negative descriptors on socket/connect/send failure, but the async caller treated every nonzero value as success and entered `DNS_QUERY_SENT`. Read timeout also bypassed the intended alternate-family retry, while exhausting both families left `DNS_RESP_FAILED` without a terminal transition. | Accept only positive descriptors, route setup/read failures through one retry state, select only an untested A/AAAA family, and fail the connection after the retry set is exhausted. Async socket registration now independently rejects invalid owners and descriptors. | `ExplicitProxyDnsState.*` plus the common async lifecycle tests. |
| DNS-002 | Resolver response correlation | The direct synchronous and asynchronous resolver accepted the first parseable datagram from the connected resolver socket without checking the DNS transaction ID, response flag or echoed question. A stale or injected packet could therefore supply an unrelated address set. Failure of `RAND_bytes` also left the request ID uninitialized. | Require successful random-ID generation, propagate the generated ID/name/type with the query, and discard packets whose transaction ID, QR bit or sole IN-class question does not match. DNS names are compared case-insensitively with an optional root dot. | `DNSFactory.CorrelatesReceivedDatagramsWithRequestTransactionId`. |
| DNS-003 | DNS request construction | The request builder accepted empty names, empty labels, labels longer than 63 bytes and names longer than the DNS wire limit. Its 8-bit label counter wrapped on long SOCKS FQDN input, and an otherwise valid trailing root dot produced an extra zero label that displaced QTYPE/QCLASS. | Validate RFC wire-size and label bounds before allocating/encoding, normalize one optional root dot, clear the output on rejection, and propagate construction failure before opening a resolver socket. | `DNSFactory.RequestBuilderEnforcesDnsNameBoundsAndNormalizesRootDot`. |
| WHK-001 | HTTP request ownership | Every webhook request allocated a cURL header list but destroyed only the easy handle, leaking the list for the lifetime of the process. The owning request object was also implicitly copyable despite holding raw cURL resources. | Free the header list during teardown and prohibit copy/move operations that cannot preserve cURL callback pointers safely. | Real-process loopback webhook E2E under ASan/UBSan. |
| WHK-002 | HTTP shutdown | A transfer-progress callback checked Smithproxy's termination flag, but cURL progress reporting remained disabled by default. A stalled webhook could therefore delay shutdown until its timeout. | Enable cURL progress callbacks and exercise shutdown while a loopback webhook deliberately withholds its response. | `integration.libcli2_process` requires bounded shutdown with an active stalled request; normal and ASan/UBSan runs pass. |
| WHK-003 | HTTP request reuse | `Request::emit()` retained its previous attempt count. Reusing an object after exhausted retries skipped the transfer loop and could return stale response metadata; payload length also relied on NUL termination. | Reset attempts per emission, initialize failure state explicitly and provide cURL the exact payload length. | Loopback E2E covers success, HTTP error and exhausted transport retries with exact payload validation. |
| WHK-004 | CLI webhook result | The asynchronous request's internal initialization hook was printed as a fake `Response: -100` before the actual server response. | Suppress non-positive internal status codes in the CLI callback while preserving the final HTTP/transport result. | Loopback CLI E2E rejects the internal response and verifies 202, 503 and transport-error 600 results. |
| WHK-005 | cURL retry/timeout | The five-second timeout applied independently to each of five attempts, so one webhook could occupy a worker for roughly 25 seconds. Every POST failure was retried, including failures after the peer could already have accepted the action. | Use one monotonic deadline, two attempts, and retry only DNS/connect failures that occur before delivery can begin. | Loopback E2E closes a connection after reading the POST and requires exactly one received copy; unavailable and stalled targets cover bounded failure/shutdown. |
| WHK-006 | cURL resource bounds | Response bodies and the asynchronous request queue were unbounded; the utility pool also scaled to twice every available CPU. A slow or hostile webhook could consume memory and create a large outbound burst. | Cap replies at 8 MiB, cap pending/running webhook work at 256, cap utility workers at 32 and expose pending/drop counters in diagnostics. | Loopback E2E rejects an 8 MiB + 1 response with status 600; focused pool tests and full process shutdown exercise bounded task teardown. |
| WHK-007 | Webhook TLS/config | Disabling TLS verification disabled chain verification but left hostname verification implicit. A queued request also read URL, TLS, DNS and interface settings at different times, allowing reload/API override races to mix configurations; clearing `hostid` retained the stale value. | Disable peer and hostname verification together when explicitly configured, and enqueue one locked settings snapshot; make host identity synchronized and reload empty values. | HTTP API integration covers override registration/unregistration and TLS selection; loopback E2E uses the snapshot request path. |
| WHK-008 | Callback/lifecycle | Reply callbacks ran while the global URL-statistics mutex was held, exceptions from response parsing could escape synchronous proxy paths, and utility workers were not joined before Smithproxy services were torn down. | Release statistics locks before callbacks, contain callback/request exceptions, stop queued work and join active cURL workers during orderly shutdown. | Deliberately stalled loopback transfer must terminate with the process; normal and ASan/UBSan process runs exercise teardown. |
| WHK-009 | Webhook statistics | URL-stat TTL was set to the literal duration as an epoch time, so entries were immediately expired; the burst detector could report fewer errors than configured and the map was never pruned. | Refresh expiry relative to current time, require the configured number of errors within the window and periodically remove expired URLs. | `WebhookStats.ErrorBurstRequiresConfiguredCountWithinWindow`, `SuccessfulUpdatesRefreshEntryLifetime`, and `ErrorQueueRemainsBounded`. |
| WHK-010 | API override | Unregistering a temporary webhook target overwrote the persistent configured TLS verification flag, changing behavior after the override expired. | WHK-011 | Accepted-response burst | HTTP 202 intentionally requests an enhanced proxy/neighbor snapshot, but every accepted connection event independently launched two more requests. | WHK-012 | Large POST latency | cURL could add `Expect: 100-continue` to large JSON/content POSTs. | WHK-013 | Utility pool diagnostics | Worker metadata was initialized once per worker from inside the worker-creation loop, allocating N² slots and making diagnostic indexing diverge from the actual worker count. | Initialize metadata exactly once before starting workers. | `UtilityThreadPool.AllocatesOneMetadataSlotPerWorker`. |
