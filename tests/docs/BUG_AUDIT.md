# Bug audit

This file records product and regression-harness defects found while expanding
test coverage. Each entry names the failure mode, impact, correction and
regression evidence so a coverage increase remains reviewable as more than a
percentage change.

| ID | Area | Finding and impact | Correction | Regression evidence |
| --- | --- | --- | --- | --- |
| PXM-001 | Proxy connect | A failed upstream `connect()` returned a negative descriptor, but the proxy registered it with the event loop and reported success. This could leave a half-created flow with invalid handlers. | Reject non-positive descriptors before monitor/handler registration and ownership transfer. | `ProxyMakerUtils.RejectsFailedUpstreamBeforeRegisteringHandlers` |
| PXM-002 | Proxy ownership | `route_existing()` temporarily adopted a caller-owned raw pointer in a `unique_ptr`. An exception while routing could delete an object still owned by the caller. | Route through a non-owning overload; the owning overload delegates with `get()`. | Production build plus the focused ProxyMaker ownership tests exercise the shared route/connect helper boundary. |
| PXM-003 | Policy routing | Failure to select or apply a configured routing target was logged but policy processing continued toward the original destination. That made a routing failure fail open. | Propagate routing failure from `policy()` and abort proxy creation. | Full native suite; routing errors now have an explicit false return path. |
| PXM-004 | UDP accept | The accepted UDP context was transferred into a child proxy before source-address resolution. On resolution failure the context was manually deleted, then deleted again when the child proxy unwound. | Resolve the source before transferring ownership to the child proxy. | ASan build and native/dataplane lifecycle runs; ownership is transferred only after the failing operation. |
| PXM-005 | Transparent source | `std::stoi` accepted trailing bytes and negative values, which could wrap into an `unsigned short` source port. | Parse the complete decimal field with `from_chars` and accept only `1..65535`. | `ProxyMakerUtils.ParsesOnlyCompleteValidSourcePorts` |
| PXM-006 | Proxy setup | Proxy creation, policy, routing and SNAT paths dereferenced missing contexts or transports on partially constructed flows. | Share one validated endpoint precondition across make/policy/route/SNAT before accessing either communication object. | `ProxyMakerUtils.RejectsMissingEndpointTransportsBeforeProxySetup`, `RejectsFailedUpstreamBeforeRegisteringHandlers`, and the full native suite. |
| TST-001 | QUIC soak | The origin counted a completed short-lived certificate-probe handshake on a later polling tick. A peer close between accept and that tick made a valid handshake disappear from the counter. | Record the handshake immediately when OpenSSL publishes the accepted connection, retaining the later check only as a fallback. | Repeated `QuicTestbed.RepeatedVerifiedReconnectsReleaseEveryIdleSession` soak. |
| TST-002 | QUIC interop | The OpenSSL client closed at stdin EOF immediately after a verified QUIC handshake, racing delivery of its first application-stream payload and making the external interop test deterministically fail. | Keep `s_client` alive until the origin confirms the echo, with a bounded poll and cleanup. | `external.quic_interop` with the system OpenSSL QUIC client. |
| OCS-001 | Async OCSP | `OcspQuery::run()` returned the same value for nonblocking I/O progress and terminal completion. `AsyncOCSP` consequently treated an ordinary connect retry as a finished `UNKNOWN` check, while a timeout could enter an unhandled state indefinitely. | Drive immediate state transitions in one bounded loop, return running only with a live BIO awaiting readiness, and terminate explicitly after target exhaustion. | `TLSIntegration.OCSPQueryExhaustsFailedNonblockingTarget` plus the OCSP/CRL sanitizer matrix. |
| OCS-002 | OCSP parsing | Public request/check helpers and signed-response CertID parsing trusted null or incomplete OpenSSL objects. Malformed inputs could be dereferenced instead of producing an unknown/fail-closed result. | Validate request components, duplicated certificates, response singles, CertID fields and digest lookup before use. | `TLSIntegration.OCSPRequestPreparationRejectsIncompleteInputs`, `TLSIntegration.OCSPQueryRejectsMissingCertificates`, signed-response matrix and revocation fuzzer. |
| OCS-003 | OCSP responders | The synchronous responder loop tested a stale local variable, so it continued after a definitive GOOD/REVOKED result and allowed a later responder to replace it. | Stop at the first current, signed, matching definitive response. | Existing multi-entry signed-response tests plus full TLS integration suite. |
| OCS-004 | OCSP target lifecycle | Target rotation freed a connection BIO without clearing its pointer or monitored descriptor. Skipping an unsupported HTTPS target could leave a dangling BIO visible to a later drive. | Clear the BIO and descriptor on every teardown and synchronously advance across failed/unsupported targets. | Async target-exhaustion test under ASan/UBSan. |
| OCS-005 | Async OCSP registration | The invoker registered and paused its parent even when a query completed synchronously (for example, no responder URL), causing descriptor zero to be tapped and the flow to remain paused. | Register and pause only a genuinely running query with a positive live descriptor. | `TLSIntegration.AsyncOCSPWithoutResponderNeverRegistersSocketZero`. |
| OCS-006 | Async OCSP ownership | Both the OpenSSL BIO and `AsyncSocket` claimed ownership of the responder descriptor. Teardown could close the same FD twice; target failover also left the event monitor on the old descriptor. | Make event registration non-owning and atomically retap whenever the query BIO changes descriptors. | ASan TLS suite plus async completion and target-exhaustion lifecycle tests. |
| WHK-001 | HTTP request ownership | Every webhook request allocated a cURL header list but destroyed only the easy handle, leaking the list for the lifetime of the process. The owning request object was also implicitly copyable despite holding raw cURL resources. | Free the header list during teardown and prohibit copy/move operations that cannot preserve cURL callback pointers safely. | Real-process loopback webhook E2E under ASan/UBSan. |
| WHK-002 | HTTP shutdown | A transfer-progress callback checked Smithproxy's termination flag, but cURL progress reporting remained disabled by default. A stalled webhook could therefore delay shutdown until its timeout. | Enable cURL progress callbacks and exercise shutdown while a loopback webhook deliberately withholds its response. | `integration.libcli2_process` requires bounded shutdown with an active stalled request; normal and ASan/UBSan runs pass. |
| WHK-003 | HTTP request reuse | `Request::emit()` retained its previous attempt count. Reusing an object after exhausted retries skipped the transfer loop and could return stale response metadata; payload length also relied on NUL termination. | Reset attempts per emission, initialize failure state explicitly and provide cURL the exact payload length. | Loopback E2E covers success, HTTP error and exhausted transport retries with exact payload validation. |
| WHK-004 | CLI webhook result | The asynchronous request's internal initialization hook was printed as a fake `Response: -100` before the actual server response. | Suppress non-positive internal status codes in the CLI callback while preserving the final HTTP/transport result. | Loopback CLI E2E rejects the internal response and verifies 202, 503 and transport-error 600 results. |
| WHK-005 | cURL retry/timeout | The five-second timeout applied independently to each of five attempts, so one webhook could occupy a worker for roughly 25 seconds. Every POST failure was retried, including failures after the peer could already have accepted the action. | Use one monotonic deadline, two attempts, and retry only DNS/connect failures that occur before delivery can begin. | Loopback E2E closes a connection after reading the POST and requires exactly one received copy; unavailable and stalled targets cover bounded failure/shutdown. |
| WHK-006 | cURL resource bounds | Response bodies and the asynchronous request queue were unbounded; the utility pool also scaled to twice every available CPU. A slow or hostile webhook could consume memory and create a large outbound burst. | Cap replies at 8 MiB, cap pending/running webhook work at 256, cap utility workers at 32 and expose pending/drop counters in diagnostics. | Loopback E2E rejects an 8 MiB + 1 response with status 600; focused pool tests and full process shutdown exercise bounded task teardown. |
| WHK-007 | Webhook TLS/config | Disabling TLS verification disabled chain verification but left hostname verification implicit. A queued request also read URL, TLS, DNS and interface settings at different times, allowing reload/API override races to mix configurations; clearing `hostid` retained the stale value. | Disable peer and hostname verification together when explicitly configured, and enqueue one locked settings snapshot; make host identity synchronized and reload empty values. | HTTP API integration covers override registration/unregistration and TLS selection; loopback E2E uses the snapshot request path. |
| WHK-008 | Callback/lifecycle | Reply callbacks ran while the global URL-statistics mutex was held, exceptions from response parsing could escape synchronous proxy paths, and utility workers were not joined before Smithproxy services were torn down. | Release statistics locks before callbacks, contain callback/request exceptions, stop queued work and join active cURL workers during orderly shutdown. | Deliberately stalled loopback transfer must terminate with the process; normal and ASan/UBSan process runs exercise teardown. |
| WHK-009 | Webhook statistics | URL-stat TTL was set to the literal duration as an epoch time, so entries were immediately expired; the burst detector could report fewer errors than configured and the map was never pruned. | Refresh expiry relative to current time, require the configured number of errors within the window and periodically remove expired URLs. | `WebhookStats.ErrorBurstRequiresConfiguredCountWithinWindow`, `SuccessfulUpdatesRefreshEntryLifetime`, and `ErrorQueueRemainsBounded`. |
| WHK-010 | API override | Unregistering a temporary webhook target overwrote the persistent configured TLS verification flag, changing behavior after the override expired. Empty override URLs were also accepted. | Reset only the override state and reject empty registrations. | `integration.http_api` verifies empty rejection, valid registration and restoration through unregister. |
| WHK-011 | Accepted-response burst | HTTP 202 intentionally requests an enhanced proxy/neighbor snapshot, but every accepted connection event independently launched two more requests. Bursty traffic therefore amplified webhook load threefold. | Preserve the 202 protocol while coalescing enhanced snapshots to one request pair per short window. | `WebhookRefreshGate.CoalescesAcceptedResponseBursts`. |
| WHK-012 | Large POST latency | cURL could add `Expect: 100-continue` to large JSON/content POSTs. Peers or intermediaries that do not implement the interim response introduce a visible wait before the body is transmitted. | Explicitly suppress the `Expect` header for webhook POSTs. | Real-process loopback webhook E2E exercises the same cURL request construction for success and failure paths. |
| WHK-013 | Utility pool diagnostics | Worker metadata was initialized once per worker from inside the worker-creation loop, allocating N² slots and making diagnostic indexing diverge from the actual worker count. | Initialize metadata exactly once before starting workers. | `UtilityThreadPool.AllocatesOneMetadataSlotPerWorker`. |
| ADR-001 | Address policy | FQDN matching dereferenced a null candidate, while an invalid CIDR object could later be passed into libcidr formatting/matching. Partially constructed or rejected configuration data could therefore crash a policy/diagnostic path. | Treat missing candidates and invalid CIDRs as non-matches and render invalid objects without calling libcidr. | `CidrAddressTest.NonsenseInput`, `FqdnAddressTest.MissingOrInvalidLookupFailsClosed`, and `FqdnAddressTest.MatchesCachedAddressAnswers`. |
| TPL-001 | Message templates | Missing templates and includes were silently accepted as empty content, partially loaded sets were published, truncated token prefixes read beyond their remaining input, and malformed block nesting could underflow the parser stack. A damaged message bundle could therefore produce blank responses or crash during startup/rendering. | Make loading transactional, retain the loader for template lifetime, reject missing/recursive/unbalanced templates, bound token parsing by remaining input and handle an unavailable page template safely. | `NlTemplate.*` and `StaticContent.*`. |
| JSON-001 | Certificate diagnostics | The JSON converter trusted certificate/name/signature/time results from OpenSSL and allocated an extension BIO even for non-verbose output without freeing it. A null or sparse certificate could crash diagnostics, while ordinary requests leaked one BIO per certificate. | Fail closed on null certificates, initialize and validate OpenSSL text buffers, tolerate absent metadata, and allocate/free the extension BIO only for verbose output. | `Jsonize.RejectsNullCertificateAndSerializesSparseCertificateSafely` and `Jsonize.SerializesCertificateNamesAndVerboseMetadata`. |
| SES-001 | Session-list completion | Completing the same worker slot twice decremented the unsigned outstanding-worker counter twice. A duplicate completion could underflow it and make diagnostics wait until timeout forever. | Make slot completion idempotent while holding the completion lock before decrementing the counter. | `SessionList.DuplicateCompletionCannotUnderflowOutstandingWorkers` and `InvalidSlotIsRejectedWithoutChangingCompletion`. |
| CFG-001 | Configuration validation | Unsigned and ranged numeric filters used `std::stoi` semantics and accepted a valid numeric prefix followed by arbitrary bytes (for example `12x`). `CfgValue` copy assignment also silently lost its empty-value and suggestion policy. | Parse the complete non-negative integer with `from_chars`, reject overflow/trailing bytes, and copy every policy field. | `CfgValue.UnsignedFiltersRequireTheCompleteCanonicalNumber` and `CopyAssignmentPreservesValidationAndSuggestionPolicy`. |
| LOG-001 | Asynchronous logging | The queue consumer held its non-recursive queue mutex while calling `write_disk()`, which acquired the same mutex again. The first dequeued message could self-deadlock the log writer; unlocked `empty()` and a plain termination flag also raced producers/shutdown. | Move one entry out under the queue lock, release it before disk dispatch, and make termination atomic. | `QueueLogger.ConsumerWritesOutsideQueueLockAndTerminates` and `NullConsumerSourceReturnsImmediately`. |
| AUTH-001 | PAM and group authorization | The PAM callback allocated one response regardless of `num_msg`, reused caller-owned password memory as PAM-owned storage, and accepted null credentials. Reentrant passwd/group lookup treated a null result as a populated structure, used undersized fixed buffers, and rejected users with more than 64 groups. | Build and own one response per supported PAM message, guard failed handles/credentials, resolve passwd and target group with sized reentrant buffers, and size the supplementary group array from `getgrouplist`. | `PamAuth.RejectsNullCredentialsWithoutEnteringPam`, `GroupLookupRejectsMissingAndNullIdentities`, and `GroupLookupFindsTheCurrentUsersPrimaryGroup`. |
| NBR-001 | Neighbor persistence | JSON restore mutated live neighbor/stat objects before complete validation and swallowed inner parse errors. A damaged record could therefore be cached under an empty/partial hostname with partially replaced state; its error path also dereferenced an uninitialized global logger. Persisted history was unbounded and empty list APIs returned JSON null instead of an array. | Parse into temporary state, publish only complete non-empty neighbors, cap restored history, skip invalid records, tolerate an unavailable startup logger, and return stable empty arrays. | `NeighborPersistence.StatsEntryRejectsMalformedInputTransactionally`, `NeighborRejectsPartialStateAndBoundsHistory`, and `HoodSkipsInvalidEntriesAndUsesArrayResults`. |
| ACC-001 | Access webhook filter | The access-response path implicitly compared arbitrary JSON types and dereferenced its parent unconditionally. Malformed replies were hard to exercise independently, and a detached/partially constructed filter crashed instead of following the documented fail-open policy. | Parse the HTTP status and JSON response through a typed decision function, accept only exact string decisions, preserve valid diagnostics, and explicitly fail open when the parent is unavailable. | `AccessFilterDecision.*` plus the full native suite. |
| FLT-001 | Sinkhole filter | The endpoint guard combined a null check with a dereference using `and`, so a missing source crashed; a missing destination was not checked at all. The diagnostic format also passed a byte count where `%s` expected a pointer, making debug logging itself crash-prone. | Return unless both endpoints and the source buffer exist, and use a type-correct size format without the stray variadic argument. | `SinkholeFilter.*`. |
| FLT-002 | Statistics filter | A detached statistics filter dereferenced a missing source endpoint, and its low-entropy diagnostic supplied a string pointer for the first floating-point conversion. The latter is undefined variadic-call behavior and could corrupt diagnostic output or crash on some ABIs. | Ignore missing input endpoints and pass exactly the two entropy values required by the format string. | `StatsFilter.EmptyFilterHasNoUsableState`, `AccountsBothDirectionsAndSerializesResults`, and `ProxyUsesTheSelectedEndpointInput`. |
