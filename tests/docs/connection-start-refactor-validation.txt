Connection-start boundary refactor
=================================

Base: 018ae4a1bddf8c0e30d14166dfe076d00f4301d0 (master).
Working branch: refactor-connection-start (local only); target: origin/master.

Scope
-----
Transparent TCP/UDP, explicit CONNECT/SOCKS TCP, SOCKS UDP and the QUIC
parent connector enter proxymaker::connect before opening the upstream.
Socket registration stays at its existing call sites. The owning connect
overload and its helper now take unique_ptr by value: failure destroys the
proxy locally rather than leaving ownership with the caller.

MitmProxy setup now runs before upstream connect, after policy and routing.
Negotiated TLS metadata is consequently not available during setup.
Destruction closes any admitted setup exactly once, including failed upstream
connects and logical-stream retirement without socket error callbacks.
The per-policy access-request filter is initialized without network I/O;
its authorization runs after setup at the pre-connect boundary.

QUIC retains one shared setup decision across the certificate probe,
staged route and forwarding session. A rejected setup never opens the probe.
Its connection-start has info.scope=transport and info.protocol=quic.
Logical streams carry scope=stream, parent_id and their downstream wire stream_id
on setup, content and stop. Parent display labels retain endpoint formatting.
The setup object sends connection-stop even if certificate preparation fails.
A verdict obtained for one resolved destination cannot authorize another.

This is the connection-entry refactor, not the subscriber-map implementation.
Existing logical H3 stream setups remain separate from parent admission and
still apply each stream's policy. Subscriptions are explicitly deferred.
The companion Spider change skips transport-only setup for HTTP addons, while
native scripts can still observe it. This does not implement QUIC/TLS addon
hooks or shared HTTP/3 client identities; existing stream inspection remains
independent. Deploy the companion Spider change before enabling this producer
with content addons on QUIC.
Proxy authentication still precedes destination discovery where required by
SOCKS negotiation; it has not been moved into this target-based gate.
